# Найденные тестами баги

Сюда записываются реальные дефекты, которые нашли тесты. Тест, воспроизводящий баг, остаётся в наборе,
но помечается как ожидаемо падающий и ссылается на запись здесь:

- Vitest: `test.fails('… [BUG A-03]', …)` (тест проходит, пока баг есть; когда баг починят — тест «упадёт», и пометку надо снять).
- Playwright: `test.fail(true, 'BUG D-02: docs/testing-bugs.md#d-02')` внутри теста или `test.fixme(…)`, если
  тест нестабилен до исправления.

Каждый поток (workstream) пишет только в свою секцию, номера — с префиксом потока (`A-01`, `B-01`, …), так
параллельные агенты не конфликтуют.

## Формат записи

```md
### A-01 · Короткий заголовок
- **Серьёзность:** critical | high | medium | low
- **Где:** src/path/file.ts:123 (предполагаемое место)
- **Тест:** tests/unit/foo.test.ts › «название теста»
- **Шаги:** 1) … 2) … 3) …
- **Ожидается:** …
- **Фактически:** …
- **Заметки:** окружение (проект Playwright, тема, ширина), частота, гипотеза о причине.
```

Серьёзность: **critical** — потеря/порча данных пользователя, приложение не открывается; **high** — ломает
основной сценарий (урок, повторение, словарь, синхронизация) без обхода; **medium** — ошибка с обходом,
неверные цифры/статусы, a11y-нарушение уровня A/AA; **low** — косметика, тексты, редкие крайние случаи.
